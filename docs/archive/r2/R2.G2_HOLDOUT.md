# Agent implementation plan: R2.G2 locked-holdout machinery

**Status:** COMPLETE; archived after the terminal source-specific R2 result

## Objective

Implement the complete, independently replayable **R2.G2 locked-holdout workflow** using synthetic or explicitly disposable holdout fixtures only.

The implementation must prove that, once model selection is immutably frozen:

1. holdout features can be materialised causally;
2. selected candidates and required controls can be refitted using only pre-holdout data;
3. forecasts and coverage can be sealed before target outcomes are accessed;
4. the first reveal irreversibly consumes the holdout;
5. metrics and conclusions use only predeclared policies; and
6. the entire closure can be independently reconstructed from immutable files.

This PR sequence must not access, derive from, or materialise the eventual real IBKR holdout.

The normative policy is that OOF work excludes all holdout decision rows, holdout materialisation occurs only after immutable selection, and the first reveal consumes the holdout for that experiment family.

This work introduces more than one trust boundary. Implement it as three ordered PRs unless explicitly authorised to combine them.

# PR A — Immutable holdout authorisation

## Purpose

Create the immutable precondition that authorises holdout preparation.

The current `SelectionManifest` freezes OOF decisions and comparator IDs, but its holdout state is deliberately fixed to:

```text
PENDING_R2_H_INTEGRATION
```

and the present fixture selection uses a pending final fitting procedure. It therefore must not directly authorise G2.

## Preserve the existing selection contract

The earlier implementation sketch named `qtrad-r2-selection-v3`; the current normative contract is:

```text
qtrad-r2-selection-v4
```

The `R2HoldoutSelectionManifest` must be constructible only from an independently verified OOF bundle and existing selection evidence. Its persisted evaluation policy is compact: it binds authenticated source semantic IDs, the projected pre-holdout target dataset ID, compact projection and opportunity binding IDs, the holdout policy/range, the ordered opportunity count and the ordered opportunity-ID digest.

Selection persistence must not embed the full holdout target source, pre-holdout target rows, a full target projection, a full opportunity registry, or opportunity tuples/lists. Every consumer derives and verifies the compact projection and registry bindings from authenticated F2/source authority; source authority owns opportunity ordering and uniqueness.

## Required fields

The new selection manifest must bind:

```text

foundation_bundle_id

market_data_source_class

holdout_scope

```

For fixture development:

```text
holdout_scope = DISPOSABLE_FIXTURE

evidence_class = IMPLEMENTATION
```

A future real selection would require:

```text
holdout_scope = CONFIRMATORY
evidence_class = CONFIRMATORY
```

but this task must not create one.

## Typed final-fitting policy

Do not retain the final fitting procedure as an unconstrained prose string.

Introduce a typed semantic contract such as:

```text
qtrad-r2-final-fitting-policy-v1
```

It must freeze:

* training range: all eligible pre-holdout decision rows;
* target maturity and purge policy;
* chronological inner-validation procedure;
* alpha candidate grid;
* loss and tie-break policies;
* preprocessing rules;
* local versus pooled membership rules;
* pooled sample weighting;
* instrument identity policy;
* intercept policy;
* Ridge solver, tolerance and iteration limit;
* final coefficient fitting procedure;
* training-prediction procedure used for bucket thresholds;
* runtime and library identity requirements; and
* failure dispositions.

The intended initial procedure should be:

```text
For each retained fitted configuration:
1. Use every eligible target row whose complete target dependency matures before holdout_start.
2. Re-run the frozen chronological tail-purged inner-validation policy.
3. Evaluate only the frozen alpha grid.
4. Apply the existing deterministic larger-alpha tie-break.
5. Fit preprocessing on the full eligible pre-holdout membership.
6. Fit the final model on that same membership with the selected alpha.
```

No holdout outcome may participate in alpha selection, preprocessing or final fitting.

## Typed research-question register

The holdout report must conclude every declared question as positive, negative or inconclusive. The questions must therefore exist before reveal.

Add a typed register containing, per question:

```text

description
candidate_configuration_id
comparator_configuration_id
metric
comparison_support
direction
threshold
minimum_support
minimum_coverage

```

Question IDs and policy content must participate in the selection identity.

No question or threshold may be added after holdout preparation begins.

## Authorisation rules

Reject selection creation unless:

* the OOF bundle independently verifies;
* the original selection independently verifies;
* source, evidence, experiment, foundation and OOF IDs agree;
* every requested holdout configuration was evaluated;
* every selected candidate follows the existing selection decisions;
* required controls are retained;
* the zero, local, pooled-local and pooled-context hierarchy remains represented where required;
* the holdout range exactly matches the experiment;
* the final-fitting policy is complete;
* every question references retained configurations;
* the experiment count is fixed;
* no holdout artefact already exists; and
* the output is new, canonical, bounded and symlink-safe.

## CLI

Suggested command:

```text

  --oof-bundle <verified-oof-manifest> \
  --selection <verified-selection-manifest> \
  --final-fitting-policy <policy.json> \
```

# PR B — Holdout preparation and forecast seal

## Purpose

Materialise holdout features, fit final pre-holdout models and generate forecasts **without reading holdout target outcomes**.

This phase must end with an immutable forecast seal. It must not evaluate forecasts.

## New contracts

Introduce only the necessary contracts:

```text
qtrad-r2-holdout-features-v1
qtrad-r2-final-fit-v1
qtrad-r2-holdout-coverage-v1
qtrad-r2-holdout-forecast-seal-v1
```

The seal should be a thin bundle referencing independently manifested children.

## Holdout feature contract

The holdout feature artefact must bind:

```text
selection_manifest_id
experiment_configuration_id
foundation_bundle_id

feature_set_name
feature_set_id
raw_feature_schema_id
ordered feature schema

holdout_range
target instrument universe
market_data_source_class
evidence_class
holdout_scope

observation_dataset_id
panel_dataset_id

rows
lineage
row_count
dataset_id
```

Every row must satisfy:

```text
holdout_start <= decision_time < holdout_end
```

Feature construction must use the same causal rules as R2.B:

```text
bar interval end <= latest_feature_bar_end
selected availability time <= feature_data_asof
```

Earlier observations from inside the disposable holdout may be used as lagged features when they would have been available at the decision time. Future observations and target outcomes may not.

Do not alter the existing OOF feature contract to allow these rows.

## Outcome-blind preparation boundary

The preparation implementation must not receive a complete `TargetDataset` containing holdout outcomes.

Add an outcome-blind projection containing only what is necessary to define forecast opportunities:

```text
target_id
instrument_id
decision_time
horizon
feature_data_asof
latest_feature_bar_end
dependency interval
eligibility metadata
```

It must not expose:

```text
log_return
label start/end prices
excursion outcomes
future target values
```

Prefer a dedicated typed port or projection rather than relying on developers to avoid reading fields from a complete target object.

Add a regression proving that changing every disposable holdout outcome leaves the complete prepared bundle byte-identical.

## Final pre-holdout fit

Create one final-fit artefact for every retained fitted configuration.

It must bind:

* holdout selection ID;
* configuration ID;
* model family;
* feature-set and schema IDs;
* horizon;
* target instrument or fixed pooled universe;
* exact pre-holdout training target IDs;
* purged and excluded memberships;
* inner fit and validation membership;
* preprocessing state;
* all alpha candidate outcomes;
* selected alpha;
* sample weights;
* intercept and ordered coefficients;
* fit disposition;
* failure reason where applicable;
* numerical diagnostics;
* application/image/Python/NumPy/scikit-learn identities; and
* final-fit semantic ID.

Use existing preprocessing and Ridge primitives. Refactor shared logic rather than reimplementing matrix construction or fitting.

The final fit is not an outer-fold fit. Do not pretend it has an outer fold ID.

## Forecast and coverage generation

For every retained holdout configuration:

* generate forecasts only from the final pre-holdout fit;
* keep zero-return as an explicit control with no fitted model;
* emit one expected coverage row for every eligible holdout opportunity;
* never replace a failed forecast with zero;
* preserve existing failure dispositions where applicable;
* bind every forecast to the selection, final fit, feature row and target opportunity; and
* exclude realised holdout values.

Coverage must retain dispositions such as:

```text
FORECASTED
FEATURES_UNAVAILABLE
INSUFFICIENT_TRAINING
INSUFFICIENT_INNER_VALIDATION
DEGENERATE_TARGET
DEGENERATE_FEATURE_MATRIX
NUMERICAL_FAILURE
MODEL_NOT_ELIGIBLE
```

Coverage denominators must come from expected opportunities rather than emitted forecasts.

## Freeze metric and bucket inputs

Before reveal, derive and seal every quantity later needed for evaluation:

* exact metric definitions;
* exact comparison-support definitions;
* exact training-derived forecast bucket thresholds;
* exact state bucket thresholds;
* required configuration pairs;
* minimum support and coverage rules;
* question register;
* selected and control configuration IDs.

Any threshold derived from final pre-holdout training predictions must follow the frozen procedure in the selection manifest.

No threshold may be computed from holdout forecasts or outcomes.

## Forecast seal

The seal must reference:

```text

final-fit children
forecast children
coverage children
metric/bucket policy child
question register
runtime identities
```

It must state:

```text
holdout_outcomes_accessed = false

```

The seal must be independently verified before reveal is possible.

# PR C — Reveal, consumption and evaluation

## Purpose

Perform the first target-outcome access, record irreversible consumption, evaluate the sealed forecasts and publish the final holdout report.

## Two-stage consumption evidence

The first attempt to read holdout outcomes consumes the holdout even if evaluation subsequently crashes.

Implement two immutable markers:

```text
qtrad-r2-holdout-opened-v1
qtrad-r2-holdout-consumed-v1
```

### Opened marker

Create this marker atomically **before loading any holdout outcome**.

It must bind:

```text
selection_manifest_id
forecast_seal_id
foundation_bundle_id
experiment_configuration_id
holdout_range
holdout_scope
opened_at
opened_by
application/image identity
explicit acknowledgement
marker_id
```

Once this marker exists:

* a normal second reveal attempt must fail;
* the marker must never be deleted on failure;
* the holdout is considered consumed;
* only a bounded recovery operation using the same immutable seal may proceed.

Use an atomic create or equivalent ownership lease so concurrent reveal attempts cannot both access outcomes.

### Consumed marker

After successful evaluation, write a separate final marker referencing:

* the opened marker;
* forecast seal;
* evaluation report;
* final bundle;
* completion time; and
* consumed state.

Do not update the opened marker in place.

## Explicit reveal acknowledgement

Require an exact acknowledgement such as:

```text
I_ACKNOWLEDGE_THIS_IRREVERSIBLY_CONSUMES_THE_FROZEN_HOLDOUT
```

The command must also require the expected selection and seal IDs on the command line.

## Holdout evaluation contract

Add:

```text
qtrad-r2-holdout-evaluation-v1
```

It must bind:

```text
selection_manifest_id
forecast_seal_id
opened_marker_id

experiment_configuration_id
foundation_bundle_id
holdout_range

target_dataset_id
forecast dataset IDs
coverage dataset IDs
final-fit IDs

metric policy
bucket policies
exact bucket thresholds
comparison support

global metrics
instrument metrics
configuration metrics
pairwise metrics
bucket metrics
coverage metrics

question conclusions
research disposition
evaluation_report_id
```

The report must use the same metric definitions and frozen policies as OOF evaluation. The normative contract permits no newly selected threshold or model.

## Question conclusions

For each frozen question, emit exactly one:

```text
POSITIVE
NEGATIVE
INCONCLUSIVE
```

`INCONCLUSIVE` must be used when predeclared support, coverage or metric-definition requirements are not met.

Do not invent an alternative threshold after seeing the result.

The report must not contain recommendations to change the model or rerun the same holdout.

## Thin final bundle

Add:

```text
qtrad-r2-holdout-bundle-v1
```

It should reference:

* holdout selection manifest;
* prepared forecast seal;
* holdout feature children;
* final-fit children;
* forecasts;
* coverage;
* opened marker;
* evaluation report;
* consumed marker; and
* replay evidence.

Do not duplicate large rows in the top-level bundle.

## CLI

The generic `holdout-reveal`, `holdout-verify`, and `holdout-recover` commands are intentionally not exposed. They have no authenticated immediate-parent contract and could imply a valid confirmatory result without the required authority chain. Use `confirmatory-g2-reveal` and `confirmatory-r2h-verify`, which require the F2 promotion, frozen selection, prepared artefact, expected identities, and irreversible acknowledgement as part of their explicit contract.

## PR C tests

Prove:

* no target loader is invoked before the opened marker exists;
* concurrent reveal attempts yield exactly one owner;
* a crash immediately after target loading leaves the opened marker;
* a second normal reveal is rejected;
* recovery accepts only the exact original seal;
* changed forecasts are rejected;
* changed target data are detected by replay;
* changed thresholds or questions are rejected;
* extra configurations are rejected;
* omitted controls are rejected;
* holdout metrics independently replay;
* conclusions independently replay;
* insufficient support produces `INCONCLUSIVE`;
* favourable and adverse fixtures produce deterministic positive/negative results;
* the final bundle rejects unknown, missing, orphaned or symlink children;
* no confirmatory claim can be produced from `DISPOSABLE_FIXTURE`;
* implementation evidence remains clearly labelled; and
* existing IG and IBKR OOF bundles continue to verify through their direct OOF contracts.

* existing selection and OOF contracts remain backward-compatible;
* a versioned immutable holdout-authorising selection exists;

* holdout preparation cannot access outcomes;

* forecasts and coverage are sealed before reveal;
* the opened marker is created before outcome access;
* a failed reveal still consumes the disposable holdout;
* repeated normal reveal is impossible;
* evaluation uses only frozen metrics, buckets, thresholds and configurations;
* every declared question receives a deterministic conclusion;
* the complete file closure independently replays;
* all work uses disposable implementation evidence;
